TERMINAL 2 — Wait for Keycloak (takes ~30-60s on first boot):
  curl -sf http://localhost:8090/realms/stocksonar/.well-known/openid-configuration > /dev/null && echo "KEYCLOAK READY"
  curl -s http://localhost:8000/health | python3 -m json.tool

HAVE THESE TABS READY:
  Tab 1: Terminal (for curl commands in Section 1)
  Tab 2: Gemini CLI (for live demo in Sections 2-6)
  Tab 3: Browser at http://localhost:8090 (Keycloak admin — admin/admin)
  Tab 4: GitHub repo page (show README, ARCHITECTURE.md with mermaid diagrams)
  Tab 5: VS Code / Cursor with project open (for code walkthrough)

PRE-CLEAR any old tokens:
  rm -f ~/.gemini/mcp-oauth-tokens.json


================================================================================
  SECTION 0: OPENING PITCH (1 min)
  What to say, what to show
================================================================================

SHOW: GitHub README or ARCHITECTURE.md system architecture diagram on screen.

SAY:
  "StockSonar is a production-grade MCP server for Indian financial
   intelligence. It wraps 6 free financial APIs — Yahoo Finance, NSE India,
   RBI, MFapi, GNews, and BSE — into 30+ MCP tools, 5 resources, and 3
   prompts. Everything is secured with OAuth 2.1 + PKCE via Keycloak, with
   three user tiers and 16 granular scopes. The whole stack runs with one
   docker compose command.

   We chose PS2 — Portfolio Risk & Alert Monitor — because it pushes
   MCP resources and subscriptions as first-class primitives, not just tools.
   The system watches your portfolio, detects risks across multiple data
   sources, and alerts you. Think of it as a personal risk analyst that
   never sleeps."

================================================================================
  SECTION 1: AUTH FLOW DEMO (3 min)
  Rubric: Authentication & Authorisation — 25%
================================================================================

This is 25% of the grade. Do NOT rush this. Show every step.

--- STEP 1A: Show the 401 ---

TERMINAL (curl):
  curl -s -D- http://localhost:8000/mcp 2>&1 | head -5

SAY:
  "An unauthenticated request to the MCP endpoint returns 401 Unauthorized.
   Notice the WWW-Authenticate header — it includes a resource_metadata URL.
   This is RFC 9728 — Protected Resource Metadata. The client uses this to
   discover which authorization server to talk to."

--- STEP 1B: Show Protected Resource Metadata ---

TERMINAL:
  curl -s http://localhost:8000/.well-known/oauth-protected-resource/mcp | python3 -m json.tool

SAY:
  "This JSON tells any MCP client: here's the authorization server
   (Keycloak on port 8090), and here are the 16 scopes this server
   supports. The MCP server and the auth server are completely separate
   — that's the Resource Server pattern from OAuth 2.1."

POINT OUT: authorization_servers array, scopes_supported list.

--- STEP 1C: Show OIDC Discovery ---

TERMINAL:
  curl -s http://localhost:8090/realms/stocksonar/.well-known/openid-configuration | python3 -m json.tool | head -15

SAY:
  "Keycloak's OIDC discovery endpoint. The client gets the authorization
   endpoint, token endpoint, and JWKS URI from here. Standard OpenID Connect."

--- STEP 1D: Show Keycloak Config (optional, if time) ---

BROWSER: Go to http://localhost:8090 → admin/admin → Realm: stocksonar
  - Show the client: stocksonar-mcp (public client, PKCE)
  - Show users: free, premium, analyst with their realm roles
  - Show the audience mapper that adds aud: "account"

SAY:
  "Three users, three realm roles. Keycloak issues JWTs with realm_access.roles.
   Our server maps those roles to OAuth scopes — tier-free gets 7 scopes,
   tier-premium gets 12, tier-analyst gets all 16. No scope is hardcoded in
   the token — the mapping lives in our server code, so we control it."

--- STEP 1E: Connect with Gemini CLI as free user ---

TERMINAL 2 (Gemini CLI):
  cd StockSonar
  gemini

  /mcp auth stocksonar
  → Browser opens → log in as: free / freepass

SAY:
  "Now watch the full OAuth 2.1 + PKCE flow. The browser opens to Keycloak's
   login page. I authenticate as the free user. Keycloak issues a JWT with
   tier-free role. Gemini CLI presents it to our MCP server, which validates
   the JWKS signature, checks issuer, audience, expiry, extracts the role,
   maps it to scopes. Connection established."

SHOW: /mcp → should show stocksonar (CONNECTED)

RUBRIC HITS:
  [x] OAuth 2.1 + PKCE end-to-end
  [x] Protected Resource Metadata (RFC 9728)
  [x] 401 with WWW-Authenticate + resource_metadata
  [x] Auth server separate from MCP server
  [x] Bearer token validation (signature, expiry, audience)

  SECTION 5: RESOURCES & SUBSCRIPTIONS (2 min)
  Rubric: MCP Design — 25%
================================================================================

TYPE IN GEMINI:
  Read these MCP resources:
  - market://overview
  - macro://snapshot
  - portfolio://holdings
  - portfolio://alerts
  - portfolio://risk_score

SAY:
  "Five MCP resources. Portfolio resources are auth-scoped — they're keyed
   to the JWT sub claim, so each user sees only their own data. market and
   macro resources are shared snapshots.

   The key PS2 differentiator: resource subscriptions. When any risk tool
   runs — say portfolio_health_check — it persists alerts to Redis, then
   fires ResourceUpdatedNotification for portfolio://alerts,
   portfolio://holdings, and portfolio://risk_score. Any subscribed client
   gets notified and can re-read the resource for updated data.

   Similarly, refresh_market_overview invalidates the cache and notifies
   market://overview subscribers."

TYPE IN GEMINI:
  Call refresh_market_overview.

SAY:
  "That just invalidated the market cache and triggered a subscription
   notification. In a real deployment, a subscribed dashboard would
   automatically refresh."

  File: src/stocksonar/middleware/http_rate_limit.py
  SAY: "ASGI middleware intercepts MCP responses, detects rate-limit markers,

  File: src/stocksonar/cache/redis_cache.py
  SAY: "TTL-based per data type. Quotes 60s, news 30min, financials 24h.
       JSON serialized, type-keyed."

7C. AUDIT LOGGING
  File: src/stocksonar/middleware/tool_guard.py
  SAY: "Every tool call is logged as structured JSON — user ID, tier, tool
       name, success/failure, timestamp. For rate limit failures, includes
       retry_after."

7D. API KEY ISOLATION
  SAY: "All upstream API keys live in server-side .env. Never exposed in
       tool responses. The Settings class loads via pydantic-settings.
       GNews has a daily quota tracker in Redis to stay under 100/day."

7E. UPSTREAM FAILURE HANDLING
  File: src/stocksonar/upstream/yfinance_client.py (get_quote function)
  SAY: "Every upstream call is wrapped in try/except. If Yahoo Finance
       fails, we return cached data or a clear error — never crash. Invalid
       tickers are caught before they poison the portfolio."

================================================================================
  IF THINGS GO WRONG — RECOVERY PLAYBOOK
================================================================================

  PROBLEM: Keycloak not ready
  FIX: Wait 30-60s. Check: curl -sf http://localhost:8090/realms/stocksonar/.well-known/openid-configuration
  BACKUP: Show the curl auth demo while waiting. Keycloak is slow on first boot.

  PROBLEM: Gemini CLI won't connect
  FIX: rm -f ~/.gemini/mcp-oauth-tokens.json && /mcp auth stocksonar
  BACKUP: Use the interactive Python script instead:
    source .venv/bin/activate
    python scripts/ps2_interactive.py --tier analyst

  PROBLEM: MCP server crashes
  FIX: docker compose logs -f mcp-server (check error)
       docker compose up -d --build mcp-server (rebuild)

  PROBLEM: Can't switch users (SSO sticks to old user)
  FIX: Open incognito browser window. Or:
    open "http://localhost:8090/realms/stocksonar/protocol/openid-connect/logout?redirect_uri=http://localhost:8090"
    rm -f ~/.gemini/mcp-oauth-tokens.json

  PROBLEM: yfinance returns no data (market closed / API issue)
  SAY: "The market is currently closed, so live price data isn't available.
       Let me show the cached data and the tool's graceful degradation."

  PROBLEM: GNews API quota exhausted
  SAY: "We've hit the daily free tier limit for GNews. The server tracks
       this via a Redis counter and returns a clear quota error rather
       than crashing. That's upstream quota awareness in action."

  PROBLEM: Judge asks about something you didn't show
  BACKUP FILES:
    docs/ARCHITECTURE.md — full technical docs with mermaid diagrams
    docs/DEMO_GUIDE.md — step-by-step with all prompts
    docs/gemini_test_prompts.md — exhaustive test prompts per tier
    README.md — setup, API reference, LLM integration
